# PRD — 스도쿠 솔버 (Sudoku Solver)

> 작성: 2026-11-25 (프로젝트 2일차. 1일차에 구현된 기능을 바탕으로 역작성하고, 남은 범위를 확정함)

## 1. 배경 / 문제 정의
스도쿠 퍼즐을 손으로 풀다 막히면 "정답"만 알려주는 사이트는 많지만, **왜 그 숫자가 들어가는지**,
**이 퍼즐이 얼마나 어려운지**, **정답이 하나뿐인 올바른 퍼즐인지**를 한 번에 알려주는 가벼운 도구는 드물다.
또한 연습용 퍼즐을 직접 만들려면 유일해가 보장되는 생성기가 필요하다.

## 2. 목표 / 비목표
### 목표
- 어떤 9x9 퍼즐이든 빠르게(어려운 퍼즐도 1초 이내) 풀이한다.
- 퍼즐이 유일해를 가지는지 검사한다.
- 유일해가 보장된 새 퍼즐을 시드 기반으로 재현 가능하게 생성한다.
- 사람이 쓰는 풀이 기법을 기준으로 난이도를 평가한다.
- 사람이 따라갈 수 있는 단계별 풀이 설명을 출력한다.

### 비목표 (이번 범위에서 하지 않음)
- 9x9 이외 크기(4x4, 16x16), 킬러/대각선 등 변형 스도쿠
- X-Wing, Swordfish 등 고급 기법 (난이도 평가는 기본 기법 + "백트래킹 필요" 단계로만 구분)
- 이미지(사진) 인식 입력, 웹 서버/계정 기능

## 3. 대상 사용자
- 스도쿠를 즐기며 막힌 칸의 힌트나 풀이 근거가 궁금한 사람
- 연습용 퍼즐을 난이도별로 만들고 싶은 사람
- 백트래킹/제약 전파 알고리즘을 공부하는 개발자

## 4. 핵심 기능
| ID | 기능 | 우선순위 | 상태 |
|----|------|----------|------|
| F1 | 퍼즐 파싱(81자리/격자 형식) · 출력 · 규칙 검증 | 필수 | 1일차 완료 |
| F2 | 비트마스크 + MRV 백트래킹 솔버 (`solve`, 파일 일괄 풀이) | 필수 | 1일차 완료 |
| F3 | 유일해 검사 (`check`) | 필수 | 1일차 완료 |
| F4 | 칸별 후보 숫자 힌트 (`hint`) | 필수 | 1일차 완료 |
| F5 | 유일해 보장 퍼즐 생성기 (`generate`, `--seed`, `--clues`) | 필수 | 2일차 완료 |
| F6 | 기법 기반 난이도 평가 (`rate`) — Naked Single / Hidden Single / Naked Pair / 백트래킹 | 필수 | 2일차 완료 |
| F7 | 단계별 풀이 설명 (`explain`) | 필수 | 2일차 완료 |
| F8 | 브라우저에서 플레이하는 단일 HTML 페이지 | 선택 | 범위 밖으로 보류 |

## 5. 사용자 시나리오
1. **풀이**: 사용자가 신문에서 본 퍼즐을 81자리로 입력해 `solve` → 완성된 격자와 소요 시간/노드 수를 본다.
2. **검증**: 직접 만든 퍼즐을 `check` → "유일해 있음" 또는 "해가 2개 이상"을 확인한다.
3. **힌트**: 막힌 칸을 `hint 퍼즐 행 열` → 그 칸의 후보 숫자를 본다.
4. **생성**: `generate --seed 42 --clues 30` → 유일해가 보장된 새 퍼즐과 난이도를 받는다. 같은 시드면 같은 퍼즐.
5. **난이도**: `rate 퍼즐` → 쉬움/보통/어려움/전문가 등급과 기법별 사용 횟수를 본다.
6. **설명**: `explain 퍼즐` → "R1C3 = 4 (Naked Single: 후보가 4 하나)" 같은 단계별 설명을 따라가며 직접 푼다.

## 6. 입력 · 출력 · 데이터 구조
- 입력: 81자리 문자열(빈칸 `.` `0` `_`) 또는 `|`, `-`, `+` 구분자가 섞인 9x9 격자 텍스트, 파일(`-f`), 표준입력.
- 내부 표현: `Grid = list[list[int]]` (0 = 빈칸). 솔버는 행/열/박스별 9비트 마스크 사용.
- 논리 풀이 단계: `Step(technique: str, cells: list[(r,c)], value: int | None, eliminated: list[(r,c,v)], reason: str)`
- 난이도 등급 규칙:
  - 쉬움: Naked Single 만으로 풀림
  - 보통: Hidden Single 필요
  - 어려움: Naked Pair 필요
  - 전문가: 위 기법만으로 막혀 백트래킹(추측) 필요
- 출력: 사람이 읽는 격자 / `--oneline` 81자리 / 종료 코드(0 성공, 1 해 없음·유일해 아님, 2 입력 오류)

## 7. 기술 스택과 선택 이유
- Python 3.10+ 표준 라이브러리만 사용 (argparse, dataclasses, random, unittest)
  - 설치 없이 바로 실행 가능, 알고리즘 학습용으로 읽기 쉬움
- 비트마스크: 후보 계산을 정수 비트 연산 한 번으로 처리 → 백트래킹 속도 확보
- `random.Random(seed)`: 전역 상태와 분리된 재현 가능한 생성

## 9. 리스크 / 제약
- 생성기에서 칸을 지울 때마다 유일해 검사를 하므로 단서 수를 너무 적게(≤ 22) 요구하면 오래 걸리거나 목표를 못 맞출 수 있음 → 목표 단서 수는 "최소 시도치"로 다루고, 도달 못 하면 가능한 최소로 반환
- 기본 기법만으로는 많은 "어려운" 퍼즐이 "전문가"로 분류됨 (고급 기법 비목표)
